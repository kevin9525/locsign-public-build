# LocSign 接手修订：以 NB 助手的核心流程为目标

日期：2026-11-05。承接用户“你来接手吧”“需要参考 NB助手 实现功能”。

## 目标与已确认范围

面向用户现有 iPhone XS Max / iOS 18.7.3，保留两个目标：免费 Apple ID 的 IPA 签名安装与续签；固定选点的全局模拟定位与恢复。参考 NB 助手的使用流程，首次允许电脑安装、配对，日常目标是手机操作。NB 官网另列出的 App Store 降级、JIT 等功能不因此自动纳入第一阶段。

## 证据与修正

- NB 官网及帮助中心（2026-11-05 读取）：IPA 签名、虚拟定位、免 Wi-Fi；首次电脑安装需 USB、解锁、信任电脑与开发者模式。官网并未公开内部协议，不能声称已确认其内部实现。
- SideStore README 明确说明使用本地 VPN 配合设备服务完成手机内安装；免费账号借助独立的 LocalDevVPN 提供所需权限。来源：https://github.com/SideStore/SideStore 。
- StikDebug 项目支持 iOS 17.4+，使用 idevice；优先研究其配对、隧道和定位会话。参考：https://github.com/StikDebug/StikDebug 。只借鉴其技术流程时不直接复制代码；采用代码必须遵守其 AGPL-3.0。
- M0 只证明电脑控制手机的链路可行，不能作为手机端独立实现已完成的依据。
- 七天限制主要来自免费账号的 provisioning profile 有效期，不能据此把开发证书期限写死为七天。
- HTTP 代理错误只是在当时环境中相关，不能推导所有 Apple 请求必须绕过所有代理。
- OTA + HTTPS 不视为免费账号安装的已验证后备方案。

## 本次接手的可交付切片

1. 修复现有签名流程：非空 Zsign 回调；签名 IPA 在返回后仍存在；临时私钥与工作目录清理；从 Entitlements 解析应用标识。
2. 测试覆盖真实异步签名入口、错误返回、真实格式描述文件及畸形输入。CI 保存原始日志、xcresult，并为测试与整个 job 设置时间上限。
3. 提供手机端设备服务连接探测：输入地址，发送 lockdownd QueryType，显示分阶段结果；仅识别传输通道可达性，不能把它显示为“已配对”或“可安装”。
4. 提供可导入 IPA、PEM 私钥与描述文件的签名/导出入口，用于验证现有签名链。免费 Apple ID 登录、安装和定位尚未实现时必须如实显示状态，不伪造成功按钮。

## 后续真机闸门

- 拔线后通过本地 VPN/隧道完成配对认证、AFC 上传与安装，而非仅 TCP 连通。
- 使用匹配账号、设备和 App ID 的 profile 签名、安装并启动；扩展必须逐个处理自己的 profile 和 entitlements。
- 设备端建立 iOS 18 开发服务通道、挂载匹配 DDI、设置与恢复定位。
- 切换到地图/其他 App、锁屏 10 分钟、断网/重启后的行为必须分别记录；不能把保持 socket 等同后台运行资格。
- 免费 Apple ID 登录优先复用实际存在的认证实现；不把凭据交给未授权第三方。

## 验证边界

本机 Windows 无 Xcode。Swift/XCTest 和设备构建必须由 macOS CI 执行；静态检查与 Python 辅助检查不能代替编译或真机验收。当前沙箱无法读取 Git Credential Manager 中的 GitHub 登录凭据；先准备可审阅代码与可重现验证命令，再处理推送。
