## 改动

- `App/Resources/Assets.xcassets/AppIcon.appiconset/`：单张 1024×1024 RGB（无 alpha）PNG，`idiom: universal`、`platform: ios`。部署目标为 iOS 17，由 actool 生成各尺寸。
  图案：蓝→青对角渐变底，白色定位针内嵌对勾，对应"签名 + 定位"。由脚本绘制，无第三方素材与许可证负担。
  SHA-256：`bacabece385319ed90f97a8b7a21e6bd9d89c2d3b20057bde19303334253cbc0`。
- `project.yml`：LocSign target 设 `ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon`；版本 0.4.10/29 → 0.4.11/30。
  `App/Resources` 已以 resources 构建阶段整体纳入，资源目录无需额外配置。
- `.ci/verify-app-icon.py`：源端检查（引用唯一、尺寸、无 alpha、工程已选择图标），`--ipa` 时检查顶层 App 含 `Assets.car` 且 `CFBundleIcons.CFBundlePrimaryIcon.CFBundleIconName == AppIcon`。
- `.github/workflows/build.yml`：打包后新增 "Verify app icon in IPA" 步骤，失败即阻断 artifact 上传。
- `Tests/BuildTools/test_app_icon.py`：7 项测试（仓库图标合格；alpha、尺寸错误、未选择图标被拒；IPA 合格、缺图标声明、缺 Assets.car 被拒）。
- `.gitattributes`：`*.png binary`、`*.json text eol=lf`。

## 与既有流程的关系

- `ProvisioningIPAPreflight` 只拒绝扩展、嵌套 App、符号链接、加密/多架构主程序与不支持的权限；`Assets.car` 与图标 PNG 是普通资源，自身续签选择本版 IPA 时不受影响。Zsign 会把它们纳入资源封签。
- 代码中无枚举 bundle 资源的逻辑（仅按名称读取 `ThirdPartyLicenses.txt`、`LocationDDI`、根证书、`embedded.mobileprovision`）。
