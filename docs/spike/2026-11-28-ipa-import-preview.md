# IPA 导入预览（0.5.5 / build 37）

## 目标与行为

选择 IPA 后，在文件卡片下展示名称、版本与构建号、原应用标识、文件大小、声明的最低系统及主应用 PlugIns 中的直接扩展列表。缺失字段显示“未提供”，不从文件名猜版本。

兼容性提示沿用现有自动签名预检：通过只表示包格式及已知签名限制检查通过，不承诺设备兼容、签名或安装成功。不支持自动签名的包保留可读元数据和具体原因；手动证书入口保持可用，但仍受既有签名引擎能力约束。

只有预检通过时才展示主应用与扩展所需的应用标识总数；该数字不是新增注册数或账号剩余额度。

复制失败或取消导入时保留旧 IPA、预览、签名标识选择和签名产物。复制成功但预览失败时切换至新文件，清掉旧预览并显示“无法读取 IPA 预览”。后台任务退出并清理临时副本后才解除导入锁。

## 审查与边界修复

独立审查确认旧预检的全量解压只按 ZIP 声明大小做预算，未核对实际输出字节。本轮会把它提前到选文件阶段，因此必须同步修复：实际解压逐块检查取消、单项声明大小及总展开量，并校验最终长度与 CRC。

回归夹具使用 4 KB 的压缩资源，保留真实 CRC，仅将 local/central header 的展开大小改成 1，避免用大文件验证资源限制。提交 `c1d99b5` 的两项回归分别要求严格预检拒绝此包，以及预览保留元数据但不可声称自动签名兼容。

[CI #92](https://github.com/kevin9525/locsign-public-build/actions/runs/46116122846) 执行 546 项 XCTest，仅上述两项断言失败，其他 544 项通过（含全部 14 项预览测试、预先取消回归及现有手动签名）。修复将预检临时目录的解压改为逐块写入，写入前要求实际输出不超过声明大小及 2 GiB 总上限，并检查取消；每项结束校验真实长度和 CRC。

审查未发现其他阻塞项。另补已有签名产物下的失败/取消断言，验证文件内容、outputURL 与旧预览保持不变。

## 真机验收步骤

1. 使用原账号和应用标识覆盖更新 LocSign，保留已有资料。
2. 导入普通 IPA，核对名称、版本、原标识、文件大小；版本缺失时应显示“未提供”。
3. 导入含小组件或分享扩展的 IPA，展开列表核对数量及标识；确认页面不会显示“剩余额度”或“本次新增数”。
4. 导入不满足自动签名限制的 IPA，核对原因及可读元数据；手动证书区仍可进入。
5. 再导入另一 IPA，确认所有预览字段换为新文件信息；无效 ZIP 应显示预览读取失败，不保留上一应用的名称或兼容状态。
6. 导入较大的 IPA 时点取消，等待清理完成；原文件、预览和已有签名产物应保留，可重新操作。
7. 用常用 IPA 回归自动签名安装和手动证书签名。选择包时的预检不会申请证书、注册 App ID 或上传 IPA。
