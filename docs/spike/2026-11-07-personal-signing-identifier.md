# 可选个人签名标识与注册错误分类

0.2.2 / build 8 真机截图显示“注册应用标识失败：Apple Developer Services 请求被拒绝（HTTP 409）”。USB 只读检查确认手机已安装这一版本。本次失败发生在注册 App ID 阶段，尚未进入证书申请；HTTP 409 本身不能确定是标识不可用、注册数量限制还是其他字段约束。

原实现先查询当前团队是否有与原 Bundle ID 完全相同的记录，未找到便原样注册。对照的官方 Feather v2.9.0 标识为 `thewonderofyou.Feather`；用户原 IPA 字节和版本尚未取得。参考 XKit 使用带唯一前缀的标识注册，LocSign 初始范围则明确保留原标识。

用户已确认增加可选“个人签名标识”，并知晓新标识的应用会独立安装，不能直接继承原标识应用的数据。

## 实现约束

- 默认保留原标识；个人模式提供稳定生成值，并在申请前显示目标标识。相同团队和原 App 生成相同值，便于后续覆盖更新。
- 原始 IPA 和原始权限先通过既有预检查，再选用目标标识。修改只发生在签名临时副本，原文件保持不变。
- 注册标识、描述文件核验、缓存复用、输出 Info.plist 和签名权限必须使用同一目标值。目标来自用户选择，不能从返回的描述文件反推并默许。
- 输入校验拒绝空标识、通配符、路径字符和超长值。改变模式或目标会清除旧签名输出。
- 仅在开发者 REST 错误响应中识别固定类别。原始错误详情只在内存中解析，不进入 UI、日志、Keychain 或文档；未识别的 HTTP 409 保持通用错误，不当作证书配额。
- 保留账号、证书复用、撤销确认和原 IPA 权限限制。

## 验证记录

回归测试先通过既有入口复现三个缺口：明确目标标识无法用于实际签名；注册冲突丢失安全原因分类；真实 URLSession 适配器丢失该分类。[旧实现回归运行](https://github.com/kevin9525/locsign-public-build/actions/runs/42360812714)的源码为 `ec8b4f7584d970e4ac7743df053bbd15f118125b`。188 项测试中，新增 3 项测试产生 4 个预期失败断言，原有 185 项通过；日志来自模拟器产物 `13570218538`。

在观察上述失败后实现 0.2.3 / build 9。签名回归会解包实际输出 IPA，读取主程序的 LC_CODE_SIGNATURE 权限区，检查新的 application-identifier 和独立钥匙串组，并确认输入 IPA 字节不变。另覆盖确定性标识、无效输入、原权限预检查、描述文件不得替换所选标识、缓存目标匹配、切换标识清理输出及注册错误保护。

独立代码审查发现并修正两处边界问题：错误详情中回显的标识（如 `com.example.registerlimit`）不能被当成注册额度证据，现只匹配已识别的完整额度语句；取消标识生成会向后台任务传递取消，主签名页也在任务结束前显示忙碌状态，避免按钮看似可用但操作被忽略。

本地 Swift 语法解析、4 项打包测试和差异检查通过。[完整验证运行](https://github.com/kevin9525/locsign-public-build/actions/runs/42364714322)的源码为 `f15a805eea286f9361faf59da3bd16f017fb1863`。模拟器/设备构建、202 项 XCTest、4 项打包测试和 IPA 打包均通过；从产物 `13571732534` 下载的日志确认 `Executed 202 tests, with 0 failures` 和 `TEST SUCCEEDED`。CI 不能视为真机签名或安装成功。

已下载产物 `13572415422`，交付文件 `LocSign-0.2.3-build9-unsigned.ipa` 共 12,907,310 字节。实际解包确认版本 0.2.3 / build 9、主程序、三枚 Apple 根证书、许可资源、未签名状态和 CRC。SHA256 为 `c73f648c2a0a843acebe93627e95d403e162d3953e210be7a756832bd3124134`。

## 真机复测

1. 使用原 Apple ID 和原 LocSign Bundle ID，经 Sideloadly 覆盖安装 0.2.3 / build 9。个人标识选项用于待签的 Feather，不要求更换 LocSign 自身标识。
2. 重新导入 Feather.ipa 和当前手机的配对文件，检测已配对设备。
3. 在 Apple ID 自动签名页开启“使用个人签名标识”。生成后的标识会出现在输入框；需要时可点“生成此团队的固定标识”重新生成。同一团队与同一原始标识的生成值不变。
4. 核对目标标识后点击“获取材料并签名”。只有材料验证和签名均成功才发布输出。后续使用本机材料时继续选用相同目标标识。
5. 如遇标识注册数量限制，应依据 Apple 结果等待额度恢复。此版本不承诺换标识能解决所有 HTTP 409，也不绕过证书撤销确认。
6. 分别记录材料申请、签名文件生成、设备安装及实际启动。若仍报错，提供完整步骤和错误码；实际 Feather 更换标识后的运行兼容性需真机确认。
