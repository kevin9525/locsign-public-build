## 已实施

- 配对文件接受 DER、PEM 证书及 DER/PEM 的 RSA 私钥，包括 PKCS#8；证书和私钥必须匹配。使用已存在的 OpenSSL 依赖在内存中转换 PKCS#12，再调用公开的 `SecPKCS12Import`，不调用私有 `SecIdentityCreate`。
- iOS 17+ 先发送 QueryType、StartSession，然后在同一 TCP 连接上升级 TLS。拒绝缺少 SessionID 或禁用 TLS 的会话；使用 GetValue 读取设备标识。不发送包含私钥的配对字典。
- TLS 只信任配对文件的根证书。0.1.1/0.1.2 使用 Basic X.509 策略校验证书链与有效期；该策略在真机上仍会拒绝 Apple 配对证书的空主体名称。0.1.3 已改为专用的 OpenSSL 私有根验证，保留签名和有效期等校验，详见上述修复记录。
- TLS 回调完整累积 TCP 分包；握手和单次读写有操作截止时间，关闭连接的等待也受限。
- 创建独立 `/PublicStaging/LocSign-<UUID>/app.ipa`，AFC 分块上传，等待 installation_proxy 的 Complete，结束或失败后尝试清理暂存文件与目录。断线时清理可能失败。
- 导入配对材料保留已签 IPA；导入、签名和安装互斥。只有安装调用成功返回才显示成功，重新签名会清除旧安装状态。

## 真机验收顺序

没有签名材料时先完成下文的独立配对检查；已有有效签名材料时再执行完整安装验收：

1. 用 Sideloadly 等已有工具为 CI 的未签名 IPA 签名，并首次安装到已信任电脑、开启开发者模式的手机。
2. 在 LocSign 中导入无扩展 IPA、匹配且有效的描述文件、相应 P12/PEM，签名并保留导出产物。
3. 导入这台手机与电脑配对后生成的 plist。导入后，已签 IPA 应仍可导出和安装。
4. 配置能连接本机设备服务的本地 VPN/隧道，填入其设备地址。当前版本不负责创建 VPN 或首次配对。
5. 执行安装，确认设备上出现目标应用并能启动。记录 iOS 版本、安装错误和能否重试；不要提供或上传配对私钥、P12 或密码。
6. 使用不匹配的配对材料、无效地址、断开 VPN 等场景验证错误提示；失败不得显示安装成功，重新签名后不得保留旧成功状态。

目标 IPA 的真实安装与启动尚未验收。免费 Apple ID 认证/描述文件申请、续签、定位、后台持续运行不属于本轮已完成能力。

## 0.1.2：无需签名材料的配对检查

用户只有通过 Sideloadly 安装的 LocSign，没有 P12 或 mobileprovision，因此将配对与服务连通性检查从签名和安装流程中独立出来。

- 在“连接”页面导入配对 plist，点击“验证配对与安装服务”。只在内存中持有导入内容；不将私钥记录到日志或提交到仓库。
- 验证配对证书和私钥，建立 lockdownd TLS 会话，通过 GetValue 读取设备标识，再分别启动并连接 AFC 和 installation_proxy，随即关闭连接。不上传文件，也不发送 Install 命令。
- 错误按配对文件、设备连接、身份认证、文件服务和安装服务阶段提示；重新检查、修改地址或重新导入会清除此前的成功结果。
- 设备地址只接受 IPv4 / IPv6 字面量，避免误填网址或域名后进入无界的 DNS 解析等待。
- 可以取消；取消发生于底层网络读写期间时，仍需等待当前会话子步骤返回或超时。取消后不会显示成功或继续检查后续服务；即时中断底层 socket 留待后续改进。

独立审阅覆盖 `16a0228..665087b`，未发现 Critical / Important 问题。记录一项 Minor：在途取消的反馈可能延迟，现有测试覆盖启动前取消。
