# Signing fixtures

`test-key.pem` and `test-profile.mobileprovision` contain deliberately public,
synthetic test material. They are not Apple-issued identities and cannot authorize
an iOS installation. The profile is a CMS SignedData container with a synthetic
certificate matching the test key. Its expiration is 2100-01-01 so tests do not
depend on this project's creation week.

`pairing-record.plist` contains synthetic pairing metadata, a matching test
certificate/key pair, and a test-only trust root. It is used only to verify
Security framework identity construction; it cannot pair with or authenticate
to a real device.

`pairing-record-pem.plist` contains the same public synthetic identity with PEM
certificates and an unencrypted PKCS#8 private key, matching the format exported
by common pairing tools. The DER and PEM variants both exercise iOS identity
import; local TLS tests also use this identity and deliberately fragment records.
`unrelated-root.der` is a separate self-signed test CA used to verify that TLS
rejects a peer outside the imported pairing trust root; its generated private key
is not retained.

`pairing-empty-*.der` are public synthetic fixtures generated by
`.ci/generate-pairing-tls-fixtures.py`. They reproduce Apple pairing certificates'
empty issuer/subject names, SHA-1 signatures, RSA-2048 keys and zero serials.
The device and root use different keys. Only the test device private key is kept.
Expired and modified-signature variants test that accepting this pairing format
does not bypass certificate validity, signature or imported-root checks. No real
device certificate, pairing identity or private key is included.

`pairing-legacy-*.der` add the missing real-device characteristic: no Authority
Key Identifier extension. The generator explicitly disables OpenSSL's automatic
AKI generation. TLS tests cover the valid root-signed leaf, another empty-named
root, invalid signature, expired/future validity, an expired root, an unknown
critical extension and an invalid CA leaf. All keys are synthetic and public.

The integration test copies the simulator host executable into a temporary IPA,
signs that copy, verifies the archive and signature presence, and deletes the
result. This tests the signing pipeline, not Apple acceptance on a physical device.

`profile-*` fixtures are generated by `.ci/generate-profile-fixtures.py` (Python cryptography). They use an unrelated synthetic root and Apple-shaped signer names solely to test explicit anchor enforcement and profile-signer policy. They cannot authorize installation. Signer/CA private keys are discarded; `test-key.pem` and `profile-other-key.pem` are deliberately public test keys. The fixtures include expired, tampered, wrong-signer and multiple-signer CMS containers.

The public build snapshot uses `SYNTHETIC-UDID` in every profile fixture;
the legacy signing fixture was re-signed with its existing public test identity.
